# Rate limits

Rate limits are applied per API key on a rolling 1-minute window. When a limit is exceeded, the API returns a `RATE_LIMITED` error with HTTP 429.

## Limits by route family

| Endpoint Family | Limit | Window |
|-----------------|-------|--------|
| **Agents** | 120 requests/min | 1 minute |
| **Calls** | 120 requests/min | 1 minute |
| **Knowledge Bases** | 60 requests/min | 1 minute |

## How limits work

Limits are enforced per API key, not per workspace. Each distinct API key has its own request budget.

When you exceed a limit, the API responds with a `RATE_LIMITED` error:

```json
{
  "error": {
    "code": "RATE_LIMITED",
    "message": "Rate limit exceeded.",
    "requestId": "req_abc123def456",
    "details": null
  }
}
```

## Best practices

- Implement exponential backoff when you receive rate limit errors.
- Batch operations when possible to use fewer requests.
- Cache responses to avoid repeated calls for the same data.
- Monitor your usage and request multiple keys if you need higher limits.
- Contact support if you need higher limits for your use case.
